Clash Mi 属于 Mihomo 配置生态中的图形客户端方向。它的核心价值不是“点一下就自动变快”，而是把配置、代理组、规则、连接和日志放进统一界面，方便用户判断一条请求最终经过了哪个节点。

本文不提供来历不明的安装包，也不把界面按钮逐个翻译，而是讲清楚第一次配置最容易出错的环节。

## 一、安装前需要核对什么

同名软件和二次打包版本可能使用相似图标。安装前至少核对：

- 应用名称和开发者信息；
- 系统版本与设备架构；
- 下载页面与软件内更新渠道是否一致；
- 是否要求安装无关证书或设备管理配置；
- 安装后请求的权限是否与网络连接有关。

iOS 用户应优先使用正规应用商店渠道。桌面端则要区分 Apple 芯片、Intel 芯片和 Windows 架构。

## 二、Clash Mi能读取什么配置

常见机场会提供 Clash 或 Mihomo 订阅。一个完整配置通常不仅包含节点，还包括：

```text
节点列表 → 代理组 → 分流规则 → DNS设置 → 规则集与其他选项
```

如果只导入单个节点链接，可能看不到完整的自动选择、流媒体、AI 或故障转移分组。需要分场景使用时，优先选择机场提供的完整配置订阅。

## 三、第一次导入订阅

1. 在机场后台复制适用于 Clash/Mihomo 的订阅地址；
2. 进入配置或订阅管理页面；
3. 添加远程配置并粘贴地址；
4. 手动更新一次；
5. 检查节点数、代理组和更新时间；
6. 将该配置设为当前配置；
7. 选择节点后再启动连接。

如果更新时出现解析错误，不要立即改 YAML。先确认链接是否完整、订阅是否有效，以及返回的确实是配置文件而不是登录页面。

## 四、怎样选择代理组

常见配置会出现以下分组：

| 分组 | 用途 | 选择建议 |
| --- | --- | --- |
| 节点选择 | 大部分需要代理的流量 | 先手动选一个稳定节点验证 |
| 自动选择 | 定期测试并挑选节点 | 适合日常，但不一定最适合特定网站 |
| AI服务 | AI对话与相关接口 | 选择长期稳定、地区一致的节点 |
| 流媒体 | 视频地区内容 | 根据目标内容地区选择 |
| 直连 | 本地和国内服务 | 保持DIRECT或配置默认值 |
| 拦截 | 广告或追踪域名 | 规则错误时可能造成应用功能缺失 |

新手不要同时修改所有分组。先让“节点选择”工作，再逐项测试 AI、流媒体和特殊服务。

## 五、规则模式为什么比全局模式更适合日常

规则模式会根据域名、IP 和规则集决定流量方向。它能避免本地服务绕远路，也能减少不必要的代理流量。

出现“全局能打开、规则打不开”时，可以这样查：

1. 打开连接日志；
2. 重新访问目标域名；
3. 找到该请求匹配的规则；
4. 查看最终选择的是直连、拒绝还是某个代理组；
5. 临时调整分组验证，而不是直接长期使用全局模式。

## 六、延迟测试应该怎样看

客户端显示的延迟通常是短请求结果，只能作为节点初筛。真实体验还受丢包、抖动、跨境路由和目标服务器影响。

可以把测试分成三层：

- **可连接**：节点是否完成握手；
- **交互体验**：网页首屏、AI回复和消息发送是否稳定；
- **持续吞吐**：视频拖动、下载和晚高峰是否明显衰减。

不要因为某个节点延迟数字最低，就长期固定使用。自动选择组也要避免测试间隔过短造成耗电和额外流量。

## 七、iOS上的常见问题

### 添加VPN配置后仍无法连接

检查当前是否有另一个客户端的按需连接配置。多个工具可能争抢系统 VPN，先停用其他配置再测试。

### 切换网络后一直转圈

先断开再连接；如果频繁出现，检查按需连接、网络变化恢复和 DNS 设置。不要同时开启多套自动连接规则。

### 后台耗电明显

降低日志级别和健康检查频率，关闭不需要的持续测速。复杂规则和频繁节点探测都会增加后台活动。

## 八、配置更新后出现异常

订阅更新可能改变代理组名称、规则顺序和节点列表。如果更新前正常、更新后异常：

1. 记录更新时间；
2. 检查是否切换到了错误配置；
3. 查看原先选中的节点是否已移除；
4. 暂停自定义覆写；
5. 重新选择代理组；
6. 必要时恢复上一份可用配置。

不建议在不了解结构时直接大范围修改 YAML 缩进。配置文件对空格和层级敏感，一个缩进错误就可能导致整份配置无法加载。

## 九、日志里最值得看的四类错误

- **订阅下载失败**：域名、网络或订阅有效期问题；
- **配置解析失败**：格式、字段或缩进问题；
- **DNS失败**：解析服务器不可达或规则冲突；
- **节点握手失败**：服务器、端口、密钥、协议或网络兼容问题。

看到错误后先归类，再决定改订阅、改 DNS、换节点还是换网络。反复重装软件通常不是最高效的办法。
