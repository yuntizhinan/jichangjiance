测速告诉你“现在大概有多快”，路由追踪则尝试回答“数据经过了哪里、从哪一段开始变慢”。对于机场线路、跨境服务、游戏和网站访问问题，二者应该配合使用。

## 一、路由追踪在做什么

网络数据从你的设备到目标服务器，通常会经过多个路由设备。路由追踪通过逐步增加数据包的生存范围，让沿途设备依次返回信息，最终形成一条按跳数排列的路径。

可以把结果理解为：

```text
本机 → 家庭路由器 → 本地运营商 → 城市/省级骨干 → 跨境或中转段 → 目标网络
```

每一行通常包含跳数、若干次延迟和一个 IP 或主机名。

## 二、Windows、macOS和Linux怎样测试

### Windows

在终端中使用：

```powershell
tracert 目标域名或IP
```

如果不需要解析每一跳的主机名，可以减少等待时间：

```powershell
tracert -d 目标IP
```

### macOS与Linux

常见命令为：

```bash
traceroute 目标域名或IP
```

不同系统和安装环境的参数会略有区别。遇到权限或命令不存在时，先查看本机命令帮助，不要直接复制不理解的高权限命令。

## 三、在线多地路由追踪有什么价值

本机追踪只能看到“你当前网络到目标”的路径。在线多地监测可以从不同城市和运营商发起测试，帮助区分：

- 只有你所在地区异常；
- 某个运营商入口绕路；
- 多个地区都在同一跨境段延迟升高；
- 目标服务器只对部分来源响应；
- 路由随时间发生变化。

测试机场入口时，目标应选择可公开验证的服务器 IP。订阅中涉及用户身份的域名和链接不适合直接提交到公开工具。

## 四、怎样读懂一行结果

示例：

```text
 6   22 ms   24 ms   21 ms   203.0.113.1
```

- `6`：第六跳；
- 三个时间：三次探测的往返延迟；
- 最后的地址：该跳回复探测的设备地址。

三次延迟接近，说明这一刻较稳定；差距很大则可能存在抖动、排队或探测优先级差异。但不能只根据单独一跳下结论。

## 五、星号和请求超时怎么判断

看到 `*` 或“请求超时”时，常见原因有：

1. 中间设备不回复探测；
2. 回复被防火墙过滤；
3. 设备降低了探测流量的优先级；
4. 确实存在丢包或路径中断。

关键是看后续：如果某一跳不回复，但后续跳数和目标都正常出现，通常不能认定这一跳造成业务丢包。如果从某一跳开始直到目标全部超时，才需要结合其他测试继续判断。

## 六、怎样找出“从哪里开始变慢”

不要寻找单个最高数字，而要看延迟是否从某一段开始持续抬升。

例如：

```text
本地入口：      5–15 ms
运营商骨干：   15–30 ms
跨境之后：    120–150 ms
目标网络：    125–160 ms
```

这种结构说明主要距离或路径变化出现在跨境段。如果某一跳突然显示 300 ms，后续又恢复到 30 ms，更多时候只是该设备回复探测较慢，不代表转发真实业务同样慢。

## 七、正向路由和回程路由为什么可能不同

从你到服务器的路径叫正向，服务器返回你的路径叫回程。两者可能使用不同运营商和入口，因此：

- 正向追踪看起来很短，实际下载仍可能绕路；
- 某个地区上传正常，下载却抖动明显；
- 不同运营商访问同一节点表现差异很大。

普通用户往往只能直接看到正向结果。判断线路质量时，还应结合连续下载、上传、晚高峰和多个地区的实际体验。

## 八、机场线路测试的正确方法

### 1. 先测入口，不要只测出口网站

入口决定本地运营商如何接入线路。若入口已经拥堵，后续节点再快也无法弥补。

### 2. 分时段记录

至少对比白天与晚高峰。路由相同但晚间延迟和抖动大幅上升，更像容量或排队问题。

### 3. 换网络对比

使用家庭宽带和手机热点分别测试。如果只有一个运营商异常，可能是入口或互联问题。

### 4. 保存目标与时间

路由会动态变化。截图时保留测试时间、来源地区、运营商和目标地址，否则不同结果难以比较。

## 九、常见线路特征怎么理解

| 现象 | 可能含义 | 下一步 |
| --- | --- | --- |
| 本地前几跳就很高 | Wi-Fi、本地路由器或接入网拥堵 | 有线连接、重启设备、换网络复测 |
| 跨地区后持续升高 | 物理距离或骨干绕路 | 多地对比并观察实际业务 |
| 晚高峰抖动明显 | 链路排队或容量压力 | 分时段记录、换入口或节点 |
| 中间一跳超时但目标正常 | 设备不回复探测 | 不单独判定为丢包 |
| 多地均无法到达目标 | 目标网络、访问策略或服务异常 | 核对目标状态与端口 |

## 十、不要把路由追踪当作唯一结论

路由追踪有局限：中间设备可能隐藏地址、降低回复优先级，路径也可能动态改变。最终判断应该同时包含：

- 多次路由追踪；
- 持续 Ping 或连接探测；
- 实际网页、视频、AI或游戏体验；
- 不同运营商与地区对比；
- 客户端日志和节点握手状态。
